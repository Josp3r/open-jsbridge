# RFC 草案 · 使用会话图片句柄进行前台上传

页面已经通过 `media.chooseMedia@1` 选了一张图。本文提议增加可选方法 `transfer.upload@1`，由原生宿主把该图上传到应用配置的业务端点。页面持有图片句柄，可以显示上传进度、取消请求并读取业务响应。原图和宿主凭据始终由原生端处理。[需求 #24](https://github.com/Josp3r/open-jsbridge/issues/24) · [候选清单 #21](https://github.com/Josp3r/open-jsbridge/issues/21)

本稿供协议评审。方法注册、JSON Schema、Web 辅助函数和原生实现属于后续交付。v1 范围为单张静态图片、单次前台 POST；后台传输、断点续传及视频另行定义。

## 调用与响应

下例是拟议的三个 wire 消息，展示同一会话的一次上传。宿主只有在当前可信主文档获准使用至少一个上传端点、能安全读取该会话的图片并支持取消时，才可在握手中声明 `capabilities.methods["transfer.upload"].versions: [1]` 和 `cancel`。页面完成握手后可用 `bridge.has('transfer.upload', 1)` 检查。进度通过可选的 `callbacks` 特性协商。

```json
{"jsb":"1.0","meta":{"sid":"session-a","timeout":60000},"rpc":{"jsonrpc":"2.0","id":"w-17","method":"transfer.upload@1","params":{"id":"0123456789abcdef0123456789abcdef","request":{"url":"https://uploads.example.com/v1/avatar","fieldName":"file","formData":{"purpose":"avatar"},"compress":{"maxEdge":1600,"quality":80}}}}}
```

```json
{"jsb":"1.0","meta":{"sid":"session-a"},"rpc":{"jsonrpc":"2.0","method":"bridge.progress","params":{"requestId":"w-17","seq":0,"chunk":{"sent":32768,"total":131072}}}}
```

```json
{"jsb":"1.0","meta":{"sid":"session-a"},"rpc":{"jsonrpc":"2.0","id":"w-17","result":{"status":201,"body":"{\"assetId\":\"avatar-42\"}"}}}
```

**请求字段。** 顶层只接受必填的 `id` 与 `request`。`id` 使用选图返回的 32 位小写十六进制句柄。以下是 `request` 的全部字段。未知字段或类型错误返回 `-32602`。[句柄 Schema](../schemas/media-id.json)

- `url` 必填，必须是绝对 HTTPS 端点。宿主按下一节的规则核对目的地。
- `method` 可省略，唯一可传值为 `"POST"`。`fieldName` 是文件表单字段名，默认为 `"file"`。
- `formData` 与 `headers` 可省略，默认空对象。两者都是字符串到字符串的映射。表单字段名和 `fieldName` 使用 1–64 个 ASCII 字母、数字、下划线或连字符；同名的文件字段与文本字段返回 `-32602`。请求头名须为合法 HTTP 字段名，按 ASCII 大小写忽略后不得重复；头值不接受控制字符。每个映射最多 16 项，两个映射的键和值合计最多 16 KiB（按 UTF-8 字节计）；超出任一预算返回 `-32006`。宿主可进一步限制端点允许的字段、头名和值。
- `compress` 可省略。它只接受整数 `maxEdge`（1–4096 像素，默认 2048）和整数 `quality`（1–100，默认 80）。两项均可单独省略。宿主可以设更低的端点上限，对超出该策略的合法请求返回 `-32003`。
- 超时只有一个来源，即 RPC 的 `meta.timeout`，Web 调用方通过 `CallOptions.timeout` 设置。`request.timeout` 属于未知字段。上传使用有限的正整数毫秒期限，显式传入零返回 `-32602`。省略时采用协议握手值，示例主动指定 60 秒。[超时与取消](../../docs/protocol.md#7-超时与取消)

**HTTP 结果。** 完整读取最终 HTTP 响应后返回 `{status, body}`。2xx、4xx、5xx 都保留实际 HTTP 状态，由页面判断业务结果。空正文返回空串；非空正文仅接受端点允许面向页面公开的 UTF-8 文本或 JSON，以字符串交付。返回上限为解压后的 32 KiB，序列化后的完整 RPC 消息还须满足握手的 `maxMessageBytes`。读取时即执行上限，超限返回 `-32006`，禁止截断后伪装成完整结果。格式或编码不符返回 `-32603`（`invalid_response`）。宿主只应登记响应正文适合向该调用方公开的端点。响应头、重定向位置和鉴权信息均不向页面交付。

## 宿主如何授权一次网络请求

1. 在可信原生通道校验 WebView、精确 HTTPS 调用来源、主 frame、document 和 `sid`。再在该会话的媒体存储中查找 `id`，检查有效期和宿主前台状态。格式正确但未知、已释放、已过期或属于另一文档的句柄统一返回 `-32003`。失效会话的消息沿用协议的安全回送与丢弃规则。降级通道禁用此方法。[协议 §10–12](../../docs/protocol.md#101-原生句柄和缩略图)
2. 由应用为每个允许的调用来源配置上传端点。以页面给出的 `url` 为查表键，只接受与预配置的完整 HTTPS URL 字符串完全相等的值（含路径和显式端口）。发请求时必须使用宿主侧预解析的目标。配置时拒绝 userinfo、query 和 fragment。没有匹配项、文件字段不获准，或附加表单/头字段不在该端点的允许范围，均在联网前返回 `-32003`。同域的不同路径也需要独立授权。
3. 通过上述校验后，宿主才向该端点注入其专用凭据。HTTP 客户端关闭共享 Cookie、凭据缓存、自动重定向及会重发 POST 的自动重试。页面不得设置认证、Cookie、代理认证、路由、消息分帧或 multipart 编码相关的头，包括 `Authorization`、`Cookie`、`Host`、`Content-*` 和 `Transfer-Encoding`；宿主注入或保留的字段按不区分大小写处理。HTTP 客户端执行正常的 TLS 服务身份校验。收到 3xx 一律以 `-32003`（`redirect_denied`）结束，包括同源跳转。[HTTP 重定向语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4)
4. 选图授权授予的是该会话的单图读取权。上传另需宿主授予该来源向该端点提交图片的权限。产品要求用户确认时，明确拒绝返回 `-32007`，此时不发送图片。日志和桥接错误只记录请求 ID、阶段、字节数和稳定原因，不记录令牌、图片、表单内容或响应正文。

## 图片与请求体

宿主在私有存储中打开句柄对应的源图，按源方向旋转或镜像，保持宽高比，按 `maxEdge` 等比缩小且不放大。对支持的静态图（含设备可解码的 HEIC）统一重新编码为 JPEG；透明像素以白色合成。省略 `compress` 时同样应用默认值。仅从已经定向、缩放的像素编码，不复制源 EXIF、GPS、原文件名或其他源元数据。无法解码为单张静态图时以 `-32602`（`unsupported_image`）结束。移动端应在解码阶段限制像素分配，不能仅依靠输入文件的字节上限。

图片只占一个 `multipart/form-data` 文件分段，使用前述文件字段名、固定文件名 `image.jpg` 与 `image/jpeg`。其余分段为获准的 UTF-8 文本字段，分隔符由 HTTP 编码器生成。JPEG 编码流最多写入 20 MiB。超过预算时立即停止编码、删除部分输出，并在发送前返回 `-32006`。两端按输出格式、像素方向、尺寸和元数据验收，允许平台 JPEG 编码器生成不同字节。[multipart/form-data](https://www.rfc-editor.org/rfc/rfc7578.html#section-4)

## 进度、期限与回收

- 本提案把 #24 中的上传进度映射到原请求的 `bridge.progress`。只有方法 Schema 声明 `x-ojsb-callbacks`、会话协商 `callbacks` 后才可发进度。通知使用原 `requestId` 和从 0 起严格递增的 `seq`，不引入独立任务 ID 或订阅。每个 `chunk` 的 `sent` 与 `total` 均为安全整数，单位是完整 multipart 请求体的字节（含各分段和边界，不含 HTTP 请求头）。`total` 固定且大于零；`sent` 统计交给网络传输层的字节，单调不减并满足 `0 ≤ sent ≤ total`，服务端是否已保存图片仍以业务响应为准。宿主可合并采样；无法获知总长时跳过进度。进度可为零条，包括未协商 `callbacks` 的情况。调用方用最终 RPC 响应判断结果。[流式回调](../../docs/protocol.md#8-流式回调callback)
- 一个 WebView 同时执行一次上传；后到的上传返回 `-32010`。会话总并发上限仍按协议处理（`-32008`）。宿主在同一会话上下文中原子校验句柄并登记上传任务，使校验、释放、开始发送可以明确排序。每次有外部副作用前复核仍持有有效授权。重复的 RPC ID 按协议去重。
- 读取、编码、写请求体和等响应都计入期限。宿主收到请求时，用剩余的 `meta.timeout`（省略时取协商默认值）启动单调时钟定时器。宿主期限先到且可安全回复时，中止上传并返回 `-32001`。Web 侧 `idleTimeout: true` 可用有效进度刷新本地等待时间；宿主期限和句柄原定的 5 分钟有效期始终独立生效。SDK 本地超时以 `-32001` 结算；`AbortSignal` 或匹配的 `bridge.cancel` 以 `-32002` 结束待处理调用。首次调用时不在前台返回 `-32003`；执行中宿主转入后台则取消并返回 `-32002`。后台检测由原生生命周期驱动，与页面是否订阅事件无关。
- 句柄在上传中到期或被释放时，中止上传并以 `-32003` 结束仍可安全回复的请求。文档切换、WebView 销毁或会话失效同样立即取消；只向仍有效的原文档投递。以首个终态为准，停止进度、关闭流、撤销网络任务并删除本次编码的临时副本。上传完成或调用方取消时，源句柄继续遵守原有释放规则。取消与超时只能终止本地工作，已送达的请求可能已被服务端处理。宿主不得自动重放；需要幂等时由业务端点显式约定。
- 连接、TLS 或读写失败且没有可交付的 HTTP 响应时，返回 `-32603`（`network_failure`）。错误按注册的数值码分派，分类原因放在 `error.data.reason`。网络失败、读取响应失败和超时都不能据此推断服务端尚未接收图片。[错误与重试](../../docs/protocol.md#4-错误)

## 双端验收

iOS 和 Android 各使用可控时钟、可观察连接与请求体的 HTTPS 测试端点，以及带方向标记和 GPS 的图片夹具。下列是提案进入标准能力前要通过的用例。

1. **成功上传。** 从真实选图取得句柄，按示例调用。服务端收到一次 POST、一个 JPEG 和允许的文本字段。核对方向、最大边长、无 GPS/EXIF、文件名与可信凭据。分别返回 201 JSON、204 空体、413 文本，核对页面收到的状态及正文。
2. **拒绝发生在出网之前。** 对跨会话、已释放或过期的句柄、未授权来源、同域未登记路径和页面传入的鉴权头，断言网络请求数为零。已授权端点返回 307 时，只收到首个请求，第二端点计数为零。包含会话凭据的内容不能出现在错误数据或日志中。
3. **资源上限。** 用超预算图片、解压后 32 KiB 加一字节的响应，以及原始正文合规但 JSON 转义后超过协商帧上限的响应，分别断言 `-32006`。损坏图片、非法 UTF-8 响应和 TLS 失败应落入各自的错误分支。
4. **进度与终态。** 对允许与未启用 `callbacks` 的会话分别测试；检查字节单位、序号和最后一次 RPC 响应。覆盖读取源图、上传到一半、请求体发送完但未获响应时取消，以及不同 ID 的并发调用和同一 ID 的重复投递。让服务器保持连接但延迟响应，使宿主期限先于句柄过期到达，核对 `-32001`。每个有效请求只结算一次，无迟到进度，后续调用可以复用并发槽。
5. **生命周期。** 上传中推进时钟至句柄到期、切后台、导航到新文档，分别检查网络取消、临时文件/缓冲区回收和旧任务的投递目标。返回前台或从 bfcache 恢复后，旧任务不会恢复。模拟服务端已收完整请求而响应丢失，断言宿主没有发出第二次 POST。
